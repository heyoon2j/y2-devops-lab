# 에이전트 작업 규칙

## 작업 시작

새 프로젝트나 날짜별 업무일지를 시작할 때는 [wiki-start](.agents/skills/wiki-start/SKILL.md) 스킬을 사용합니다.

1. [README.md](README.md)에서 목표, 완료 조건, 실행·검증 방법을 확인합니다.
2. [STATUS.md](STATUS.md)에서 현재 이정표와 대상 작업을 확인합니다.
3. 변경 범위에 맞춰 [아키텍처](docs/ARCHITECTURE.md)와 [입출력 명세](docs/INPUT_OUTPUT.md)를 확인합니다.

## 원본을 바탕으로 문서 갱신

새 자료를 넣은 뒤에는 [wiki-raw-sync](.agents/skills/wiki-raw-sync/SKILL.md) 스킬로 관련 문서를 한 번에 갱신할 수 있습니다.

1. [raw/](raw/)에 요구사항 원문, 회의록, 승인된 결정의 원본을 보관합니다. 원본 내용을 요약본으로 덮어쓰지 않습니다.
2. 확정된 목표·범위·완료 조건은 [README.md](README.md)에, 구성 요소·데이터 흐름·설계 결정은 [아키텍처](docs/ARCHITECTURE.md)에 반영합니다. 바뀐 내용에 원본 파일 링크를 붙입니다. 현재 구현을 설명하는 내용은 [src/](src/)와 [tests/](tests/)에서도 확인합니다.
3. 자료가 서로 충돌하거나 결정이 미확정이면 [STATUS.md](STATUS.md)의 확인할 사항에 남깁니다. 확정된 후속 작업은 작업 항목 표 맨 아래에 추가합니다.

## 작업 종료

1. README에 적힌 관련 검증을 실행합니다. 실행할 수 없으면 확인할 사항에 이유를 남깁니다.
2. [LOG.md](LOG.md)에 작업 ID, 확인한 결과와 근거, 필요한 다음 행동을 기록합니다. 기존 날짜 항목과 수동 기록을 보존합니다.
3. [wiki-log-sync](.agents/skills/wiki-log-sync/SKILL.md)로 업무일지를 [STATUS.md](STATUS.md)에 반영하고 진행률을 갱신합니다.

## 정기 점검 루틴

- 권장 실행 시점은 평일 업무 종료 무렵입니다. 작업 종료 루틴과 같은 문서를 갱신하므로 두 실행이 겹치면 순서대로 처리합니다.
- 조회할 수 있는 프로젝트 PR·이슈·커밋을 오늘 기록 및 작업 항목과 대조합니다. 새 근거가 확인되면 작업 종료 절차의 문서 갱신 단계를 적용합니다.
- 접근할 수 없는 자료나 완료 여부가 애매한 항목은 확인할 사항으로 남깁니다. 기존 일지의 결정, 근거, 수동 기록을 보존합니다.
