# 프로젝트 위키 시작

요청에 따라 신규 프로젝트 또는 업무일지 절차를 적용합니다. 대화와 작업 경로에서 대상을 확인하고, 후보가 여러 개라 안전하게 선택할 수 없으면 대상만 확인합니다.

## 신규 프로젝트 만들기

1. 사용자가 지정한 템플릿을 사용합니다. 지정이 없으면 이 스킬이 포함된 프로젝트 위키 템플릿의 루트를 사용합니다. 루트에서 README, AGENTS, STATUS, LOG 및 docs 아래 문서의 형식을 확인합니다.
2. 지정한 대상 경로에 생성합니다. 경로가 없으면 상위 경로에서 `/workspaces/` 규칙이 있는 위키의 `.gitignore`를 찾아 그 옆의 `workspaces/<프로젝트명>/`에 생성합니다. 규칙이 없는 독립 템플릿은 템플릿과 같은 상위 폴더에 생성합니다. 기존 파일이 있는 경로는 사용자가 기존 프로젝트에 초기화를 요청한 경우에만 사용하고, 빠진 파일과 디렉터리만 추가합니다.
3. `README.md`, `AGENTS.md`, `STATUS.md`, `LOG.md`, `docs/ARCHITECTURE.md`, `docs/INPUT_OUTPUT.md`의 형식을 사용합니다. `raw/`, `src/`, `tests/`와 `.agents/scripts/update_progress.py`와 템플릿의 위키 스킬을 함께 구성해 AGENTS의 링크와 다음 호출이 이어지게 합니다. 템플릿에 실제 프로젝트 자료와 기록이 섞여 있다면 빈 양식과 규칙을 가져옵니다.
4. 사용자에게 받은 프로젝트명, 담당자, 목표와 완료 조건을 채웁니다. 확인되지 않은 값은 미정으로 두고 예시 작업은 실제 작업으로 등록하지 않습니다. 확정된 이정표나 작업이 없으면 표 헤더와 집계 기준을 유지하고 현재 이정표와 진행률을 미산정으로 표시합니다.
5. 생성한 구조와 내부 링크를 확인하고, 대상 경로와 남은 입력 항목을 알려줍니다.

## 업무일지 시작하기

1. 대상 프로젝트의 `LOG.md` 형식과 `STATUS.md`의 현재 상태와 다음 행동을 확인합니다. 일지 파일이 없으면 템플릿의 `LOG.md` 형식으로 만듭니다.
2. 요청한 날짜를 사용합니다. 날짜를 지정하지 않으면 Asia/Seoul 기준 오늘을 사용합니다. 날짜 제목이 없으면 `## YYYY-MM-DD`를 만들어 날짜 내림차순에 맞는 위치에 넣습니다. 이미 있으면 그 항목을 사용합니다.
3. 사용자가 준 작업 정보와 확인한 근거를 해당 소제목에 반영합니다. 시작 단계라면 알려진 다음 행동만 적고, 기록할 내용이 없으면 날짜 제목만 둡니다. 기존 일지의 수동 기록을 보존하고 같은 날짜와 내용을 중복 추가하지 않습니다.
4. 수정한 파일과 해당 날짜를 알려줍니다.
